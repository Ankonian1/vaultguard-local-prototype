Free experimental desktop package

Check a number against a declared reference.

VaultGuard checks explicitly labeled numeric assertions in the active editor. You provide the reference values; it reports matches within tolerance, mismatches and input diagnostics.

Actual Obsidian host compatibility is unverified. This package has been checked with a headless host stub, not inside Obsidian. It does not check ordinary prose, prove consistency, synchronize notes or establish that a reference is true. Use a disposable test vault with synthetic text first.

One small, explicit check

In the active note, put this standalone line:

members = 120

Run the command and paste this declaration into its modal:

[{"id":"members","value":"100"}]

The expected result is a mismatch on line 1. Values in declarations must be decimal strings. Matching is by exact, case-sensitive ID—not by nearby words or inferred meaning.

  1. In a disposable desktop test vault, create .obsidian/plugins/vaultguard-local-prototype/. The hidden .obsidian folder is inside that vault.
  2. Save both downloads directly in that folder with their exact names: main.js and manifest.json. Ensure your browser has not added a text-file extension.
  3. Reload Obsidian, then use its community-plugin settings to allow and enable the local plugin. Host UI and compatibility have not been validated by this project.
  4. Open an editable note containing the synthetic example. Find Check explicit assertions in active editor in the command palette. Paste the declaration above and select Check captured note.

The note is captured when the command opens. Later editor changes are not included until you reopen it. To remove the experiment, disable it and remove its plugin folder.

The boundaries matter

  • Only standalone ID = decimal assertions are checked. IDs use ASCII letters, digits and underscores, beginning with a letter or underscore. Leading indentation is unsupported. Ordinary prose is unchecked.
  • Nonzero references use an inclusive 0.5% tolerance; zero uses an absolute 0.005 tolerance. This is a comparison rule, not a statement of acceptable real-world error.
  • At most 100,000 note string code units and 20 declarations; numeric magnitudes up to 1015. Decimal strings may have a sign and fractional part, but no exponent, commas, infinity or NaN.
  • Unknown IDs, invalid values and repeated assertions produce diagnostics. Repeated valid assertions are reported separately; none wins automatically.
  • Code handling is narrow: paired column-zero fences and fully standalone single-backtick lines are skipped. Other code or indentation may produce unchecked diagnostics. This is not a full Markdown parser.
  • No cross-note scan, file writes, network requests, saved settings, automatic corrections, semantic decision checks or mobile support. An empty result is not a clean bill of health.
